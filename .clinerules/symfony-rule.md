Symfony 7.4 & Docker Project RulesThis project is a Symfony 7.4 application running inside Docker containers with a MySQL database. You must strictly adhere to the following operational guidelines.1. Command Execution (Docker Strict)NEVER run php, composer, or bin/console directly on the host machine.ALWAYS execute commands inside the Docker container using docker compose exec.Note: Assume the main PHP container is named php (verify the exact service name in compose.yaml if commands fail, it might be app or php-fpm).Allowed Examples:docker compose exec php php bin/console cache:cleardocker compose exec php composer require [package]docker compose exec php php bin/console make:entity2. Database & Migrations (CRITICAL PERMISSION REQUIRED)STRICT RULE: You are FORBIDDEN from executing any schema-altering or destructive database commands without explicit confirmation from the user.Whenever you need to apply migrations, drop the schema, load fixtures, or run raw SQL queries that alter data, you MUST pause and ask the user: "Do you authorize me to run this database command?"Commands requiring permission include (but are not limited to):docker compose exec php php bin/console doctrine:migrations:migratedocker compose exec php php bin/console doctrine:schema:update --forcedocker compose exec php php bin/console doctrine:fixtures:loaddocker compose exec php php bin/console doctrine:database:drop --forcePermitted without asking: Generating migrations (make:migration) or checking status (doctrine:migrations:status).3. Symfony 7.4 & PHP Coding StandardsAttributes: Always use PHP Attributes for routing (#[Route]), Doctrine ORM mapping (#[ORM\Entity], #[ORM\Column]), and Validation. Do not use YAML, XML, or old Doctrine annotations.Strict Typing: Always use scalar type hints, return types, and typed properties (PHP 8.2/8.3 features).Constructor Property Promotion: Use it whenever possible for dependency injection in controllers and services.Dependency Injection: Rely on autowiring and autoconfiguration.4. Environment & SecretsNever hardcode database credentials or API keys in the code.Always use environment variables defined in .env or .env.local.The MySQL connection string must target the docker database service (e.g., mysql or db) instead of 127.0.0.1.
